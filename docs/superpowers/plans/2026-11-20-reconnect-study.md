# 在线多目标跟踪重连实验计划

目标是交付可运行的重连模块、可复算的风险及恢复结果和会议稿实验章节。公开数据上的独立实验记录从本计划开始。

## 数据与阶段

| 阶段 | 任务与验收 | 工具和技能 |
|---|---|---|
| R0 | 核对公开数据、源码和权重，记录标注、帧率、视频分组、训练来源和摘要。确认 CUDA 实际执行。 | 文献检索、并行协作、验证 |
| R1 | 固定人类标注与检测框的一对一配对。统一定义自然漏检后的恢复事件，并核对至少一个真实案例。 | 测试驱动与研究设计 |
| R2 | 接入在线跟踪器并记录全部重连动作。无门控输出与原始跟踪器核对，拒绝后需要保证后续轨迹实际改变。 | 子代理开发、测试驱动 |
| R3 | 用开发集训练有明确结构的重连评分，确认简单阈值和学习评分对照。用 RTX 3060 Ti 推理或训练并记录显存、时长与设备。 | 研究设计、统计审查 |
| R4 | 以原始来源视频为校准单位，用固定的有限策略族计算风险上界。报告实际接续数量和是否有有效的认证工作点。 | 统计审查、验证 |
| R5 | 锁定策略后在独立公开数据实测，并核对第二跟踪器或第二公开域的适用范围。 | 实验与代码审查 |
| R6 | 生成主结果、风险与恢复曲线、消融、失败案例、整体跟踪指标和时延。 | 科研绘图、统计审查 |
| R7 | 写成可投稿的实验章节和复现说明，复核每个结果的数据来源和命令。 | 学术写作、交付验证 |

## 口径

- 针对可评估标注的对象，在冻结检测中缺少匹配框且随后匹配到同一真实身份，形成自然漏检恢复事件。公开数据的人员类别与忽略标注规则按各数据集释出规定处理。人工删框仅为单列压力测试。
- 恢复率以同一批检测与真值定义的机会为分母。风险以策略实际执行的重连为计数对象。另报未接、错接、原轨迹本身缺失，以及可评估范围外的动作。正式风险策略需明确标注不可评估动作的处理规则。
- 先在开发集验证事件数量、错误类型和得分区分力。开发集用来决定窗口、得分、阈值网格和最低接受量，再锁定校准和测试协议。每个候选门控从同样的原始检测回放完整独立视频。
- 预期基础评分用检测置信度、运动几何、间断时长与一对一候选歧义。开发数据用来比较原关联分数和训练型评分。后者应通过成对或条件模型学习同一候选环境中正确重连与错误重连的区分力，并逐项消融。
- 主要统计目标为事件加权的总体错接率。用源视频级的错误数和执行数检验目标，整体恢复率、总体跟踪指标及延迟单列。最终推断须记录抽样假设、阈值选择步骤和有效样本量。

## 工作目录与责任

- `reconnect_study/tracker.py` 由跟踪适配评审负责。
- `reconnect_study/risk.py` 由统计评审负责。
- `reconnect_study/data_setup.py` 由数据评审负责。
- 根代理负责事件评价、学习评分、运行编排、结果审查和论文实验章节。
- 新下载放在 `data/reconnect_study`，运行证据放在 `runs/reconnect_study`。现有项目没有可用 Git 提交，实验代码在独立子目录实现。
